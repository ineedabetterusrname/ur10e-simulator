# Grasshopper & `Robots` Plugin Guide

The simulator's **Code lab** tab lets students test Grasshopper toolpaths on the simulated UR10e—with real velocity limits, 3D trajectory preview, and collision checks—before running on the physical robot.

---

## Method 1: Using the Custom Grasshopper Sync Node *(Recommended — Zero Copy-Paste)*

We ship a ready-to-use Grasshopper component (`UR10e_Sim_Sync.ghx`) right inside the simulator so you don't need to write any Python or manually export files.

### Step 1 — Download & Drop the Node into Grasshopper
1. Open the simulator's **Code** tab (right panel) and click **`⬇ GH Node`**.
2. Your browser will download **`UR10e_Sim_Sync.ghx`**.
3. Drag and drop `UR10e_Sim_Sync.ghx` from your Downloads folder **directly onto your open Grasshopper canvas** in Rhino.
4. A component named **`UR10e Sim Sync`** will appear on your canvas.

### Step 2 — Wire Your Toolpath into the Node
The **`UR10e Sim Sync`** node has four optional inputs (`Code`, `P`, `J`, `F`) and one output (`Status`):

| Input | What to connect | When to use |
|---|---|---|
| **`Code`** | Connect the **`Code`** output of the **Robots** plugin's `Create Program` component | When building your robot program with the **Robots** plugin |
| **`P`** | Connect a list of Grasshopper **`Plane`s** (TCP target planes in robot base coordinates) | When working with native Grasshopper planes without plugins |
| **`J`** | *(Optional)* List of joint strings `"j1,j2,j3,j4,j5,j6"` in degrees | When specifying initial joint-space moves (e.g. a safe start pose) |
| **`F`** | *(Optional)* Custom output file path | Leave unconnected to automatically save to your `Desktop`:<br>• `~/Desktop/ur10e_sim_live.script` (when `Code` is connected)<br>• `~/Desktop/ur10e_sim_live.json` (when `P` or `J` is connected) |

*(Connect a Grasshopper Panel to the node's **`Status`** output if you want to verify the exact path where the file is being written.)*

### Step 3 — Start Live Sync in the Web Simulator
1. In the simulator's **Code** tab, click **`🔄 Live Sync`** *(supported in Chrome, Edge, and Brave)*.
2. In the file picker, select **`ur10e_sim_live.script`** (or **`ur10e_sim_live.json`**) on your **Desktop**.
3. **That's it!** Whenever you adjust a slider or move geometry in Rhino/Grasshopper:
   - The `UR10e Sim Sync` node updates the file on your Desktop automatically.
   - The web simulator detects the change within `0.4s`, redraws the **cyan 3D TCP toolpath preview**, and drives the UR10e along the new path.

*(Using Safari or Firefox? Click **`Load file…`** instead of `🔄 Live Sync` and select `ur10e_sim_live.script` or `ur10e_sim_live.json`.)*

## Method 2: Direct `.script` Upload or Paste from the `Robots` Plugin

If you already have a `.script` file generated by the **Robots** plugin's `Save Program` component (or Polyscope):
- **Upload file:** Click **`Load file…`** in the Code tab, choose your `.script` file, and click **`▶ Run`**.
- **Or Copy & Paste:** Right-click a Panel connected to `Create Program → Code` → **Copy Content**, paste it directly into the Code Lab code editor, and press **`▶ Run`** (`Ctrl+Enter`).

### Supported URScript Commands
- `movej([j1, j2, j3, j4, j5, j6], a=..., v=...)` and `movej(p[x, y, z, rx, ry, rz], ...)`
- `movel(p[x, y, z, rx, ry, rz], a=..., v=...)` and `movep(p[x, y, z, rx, ry, rz], ...)`
- `set_tcp(p[x, y, z, rx, ry, rz])`
- `sleep(seconds)`
- `twofg_grip_external(id, width_mm, force, speed)` (drives the simulated OnRobot 2FG7 gripper)

## Method 3: JSON / CSV Toolpath Upload

You can also upload a `.json` or `.csv` file via **`Load file…`**:

```json
{
  "units": "deg",
  "moves": [
    { "type": "joints", "q": [0, -90, -90, -90, 90, 0], "v": 60 },
    { "type": "pose",   "pose": [-0.4, -0.29, 0.5, 0, 3.1416, 0], "v": 0.25 }
  ]
}
```

- `joints` — `q` in `units` (`deg` default, or `rad`); `v` = leading-axis speed in units/s.
- `pose` — `[x, y, z, rx, ry, rz]`: metres + rotation vector (radians) in the **robot base frame** (Z-up, matching the `+X (base)`, `+Y (base)`, `+Z` arrows shown in the simulator); `v` = TCP speed in m/s. Values that look like millimetres (`>10`) are auto-converted to metres.
- Plain **CSV** also works: one line per waypoint, `j1..j6` in degrees, optional 7th column = speed (deg/s).

## Coordinate System Tips for Rhino & Grasshopper
- **Origin & Axes:** Place your robot base at the Rhino World Origin `(0, 0, 0)` with **+Z pointing up**. In the simulator, toggle **`Axes`** in the top viewport bar to see the red **`+X (base)`**, green **`+Y (base)`**, and blue **`+Z`** arrows along with the **`1.3m max reach`** boundary circle.
- **Units:** The `UR10e Sim Sync` node automatically converts your Rhino document units (`mm`, `cm`, `m`) into metres.
- **Tool Orientation:** When using `Plane` targets (`P`), the plane's **X, Y, Z axes** define the TCP frame orientation. For a downward-pointing tool (e.g., picking bricks from above), the target plane's **+Z axis should point straight down `(0, 0, -1)`** (since the UR flange/tool +Z axis points out of the tool).
